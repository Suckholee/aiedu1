# 가입·로그인 권한 점검

2026-10-19. 가입 경로는 카카오 OAuth와 기존 Google/Firebase 인증이다. 별도 회원가입 버튼 없이 첫 소셜 로그인 시 활성 기본 회원을 생성한다. 신규 회원에게 `admin`, `operations`, `finance` 역할을 자동 부여하지 않는다. 지정 관리자와 기존 회원 신원 연결은 유지한다. 이름·이메일·클라이언트 캐시만으로 관리자 역할을 얻을 수 없다.

확인한 오류 가능성과 수정:

- Google 팝업이 완료되어도 Supabase 회원 연결이 진행 중일 수 있었다. 이제 팝업 완료와 Firebase 리스너가 같은 연결 작업을 공유하고, 유효한 LMS 회원이 확인된 뒤 성공 안내를 표시한다.
- 계정 전환·로그아웃 시 진행 중인 이전 연결을 중단한다. 이전 계정의 결과와 캐시가 새 계정에 반영되지 않도록 현재 UID도 확인한다. 실패 시 다시 연결할 수 있고 API 요청은 제한 시간 안에 종료한다.
- Kakao 호환 Firebase 계정을 동시에 생성할 때 UID가 이미 생겼다면 기존 사용자를 다시 조회한다. 정지 계정은 계속 차단한다.
- 실제 브라우저 로그에서 이전 Firestore `users` 프로필 동기화의 쓰기 권한 거부를 확인했다. 회원 원장은 서버에서 검증하여 Supabase에 저장하므로 중복 클라이언트 Firestore 쓰기를 제거했다. 기존 Firebase 자료와 규칙은 변경하지 않는다.
- 가입·로그인 모달과 완료 화면의 제목을 맞추고 회원 연결 오류를 실제 안내로 표시한다. 아직 연결에 실패한 상태를 로그인 성공으로 안내하지 않는다.

DB 회귀 검증: 새 Google/Kakao 회원 생성, 동일 가입 재시도, 기본 역할 없음, 본인 프로필 SELECT, 다른 회원/관리자 정보 보호, 프로필 직접 수정/권한 직접 추가/가입 RPC 위조 차단, 정지 회원 접근 차단, 기존 관리자 역할 유지 18개. 연결 경합·취소·재시도 검증 추가. 운영 설정 감사는 신규 가입 허용, Kakao 공급자 활성, Google 운영 도메인, 기존 회원/역할 수와 익명 데이터 접근 차단을 읽기 전용으로 확인한다.

계정 간 이메일만으로 자동 병합하지 않는다. 이메일이 같아도 기존에 다른 신원으로 연결된 계정은 원래 로그인 방식으로 접속하거나 관리자 확인을 거친다. 선택 사진 권한은 필수가 아니다. 외부 공급자 장애·팝업 차단·사용자 취소는 정상 가입 권한 문제와 구분한다.

운영 읽기 점검 결과: 가입 허용 true, Kakao 활성 true, Google 운영 도메인 허용 true. 회원 8명(관리자 1명, 일반 회원 7명). 익명 비공개 테이블 조회 및 신원 연결 RPC 호출 차단. 배포 `dpl_BTrrXcpZwdwmhqwUeEtdihaXezrD`의 HTTP 검증 45개 통과. 참고: https://supabase.com/docs/guides/auth/server-side/creating-a-client 및 https://supabase.com/docs/reference/javascript/auth-admin-generatelink .

최종 배포: `dpl_CM72DbKnh7JN71KJEjkTdzfPaj3j` (중복 Firestore 쓰기 제거 포함). 실제 Google 계정 선택 후 Firebase 외부 인증 반환 팝업이 빈 화면으로 대기하다 종료되어, 이 점검에서는 브라우저 로그인 완료를 확인하지 못했다. 운영 계정/권한 설정과 서버 API 검증은 통과했으며, 실제 신규 소셜 회원가입을 모두 성공했다고 간주하지 않는다. 사용자가 최신 로그인 창에서 직접 확인할 수 있도록 요청했다. 기존 멤버나 권한을 임의로 추가/변경하지 않았다.

후속 전환 점검에서 세션 복원과 기존 저장소 연결을 추가 분리했다. 최신 구조·검증 범위는 `lms-transition-audit.md`를 따른다.
