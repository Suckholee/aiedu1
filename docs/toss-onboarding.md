# 토스페이먼츠 신청·연결 상태

2026-10-19. 사용자가 카카오 본인인증 완료를 알려준 뒤 토스 신청 화면에서 **‘신청서 접수가 완료됐어요’**를 확인했다. 현재는 심사 대기이며, 심사가 완료되면 카카오 알림톡이나 이메일로 안내한다. 접수 완료를 계약·심사 승인·카드 결제 활성화로 취급하지 않는다. 민감한 본인인증 정보는 저장소에 기록하지 않는다.

사용자가 퀵오픈 신청을 선택하고 신청인·계좌 입력 후 판매 상품 정보 단계에서 이어서 진행하도록 요청했다. 대상 사이트는 https://aiedu1.vercel.app 이다. 상품 분류는 실제 판매 중인 오프라인 강의에 맞춰 `교육 및 학습 → 기타교육기관`으로 정리하고, 일회성 특강 설명을 입력했다. 구독형 판매는 해제했다. 최고가 600,000원·평균가 300,000원은 사용자의 명시적 요청으로 유지한다. 이 신청서 가격은 실제 10/27 특강료 150,000원을 변경하지 않는다.

접수 결과 화면에는 가입비 면제(0원), 연관리비 1년 면제(0원)가 표시됐다. 정산 전 별도 안심정산플랜 가입이 필요하며 신청 정산한도는 10,000,000원, 안내된 보험 가입 필요 금액은 2,500,000원이다. 이 금액은 납부액이 아닌 담보금액이다. 실제 안심정산플랜 결제 화면은 **월 정산한도 10,000,000원·1년 이용료 13,250원**을 표시한다. 해당 서비스는 보험상품이 아니라는 안내가 있으며, 시작일은 기본값으로 결제일 기준이다. 약관 동의·유료 계약·결제는 사용자가 직접 완료하도록 인계했으며 완료 여부는 아직 확인하지 않았다. 홈페이지 심사 안내는 하단 사업자 정보, 실제 판매 상품·가격, 환불·제공 정책 및 필요시 결제 화면 캡처를 요구한다.

## 홈페이지 심사 준비

메인 랜딩과 LMS 공통 하단에 동일한 판매자 정보를 노출한다. 상호·사업자번호·대표자·사업장 주소는 2026-08-12 사업자등록증명, 전화·이메일은 대표자 명함에서 확인했다. 원본 증빙이나 주민등록 관련 정보는 공개하지 않는다. 공개 연락처는 `lib/merchant.ts`, 표시 컴포넌트는 `components/layout/BusinessInfo.tsx`에서 함께 관리한다. 확인되지 않은 통신판매업 신고번호는 임의로 기재하지 않는다.

`/service-policy`에 현재 오프라인 강의의 제공 일시·장소 확인 방법, 실물 배송·배송비 없음, 신청·납부 확인·수강 승인 구분, 자료 이용 방법과 연락처를 공개한다. `/refund-policy`에는 연락처를 추가하고 기존 승인된 환불 기준은 유지한다. 두 안내는 회원정보 입력을 마치기 전에도 읽을 수 있다. 과정 상세·신청 동의 안내와 양쪽 하단에서 연결한다. 판매 과정이 없는 카테고리 필터는 숨기고, 10/27 특강의 실제 수강료 150,000원은 유지한다.

검증: webpack 프로덕션 빌드·타입 검사 통과. 비로그인 HTTP로 메인·과정 목록·신청·환불·제공 안내의 사업자 정보와 정책 링크를 확인하고, 공개 과정 API의 실제 150,000원 가격 및 상세 안내 연결을 확인했다. 실제 신청·결제·환불 데이터는 생성하지 않았다. 카드 결제창 캡처는 PG 연결 후 실제 동작을 검증한 화면으로 준비해야 하며, 현재 심사 제출이 끝났다고 간주하지 않는다.

사용자는 2026-10-19에 1개월 이내 오프라인 강의의 환불 정책을 신청서·사이트에 동일하게 반영하도록 승인했다. 공개 URL은 `/refund-policy`이며, 공통 원문은 `lib/lms/refund-policy.ts`에 둔다. 개강 전 전액, 개강 후 총 수업시간의 1/3 경과 전 2/3, 1/3 이상~1/2 미만 1/2, 1/2 이상 개인 사유는 미환불이다. 주최 측 취소·변경, 접수 방법·시점, 원결제수단으로 원칙적 3영업일 이내 처리와 더 짧은 법정기한 우선, 별도 위약금·PG 수수료 미공제, 법정 소비자 권리 우선도 함께 고지한다. 이전 신청 화면의 `개강 3일 전 / 1일 전 70%` 문구는 공통 정책으로 교체한다. 정책 게시 자체는 환불 API 실행이나 수납·정산 기록 변경을 의미하지 않는다.

문구 작성 시 참고한 공식 자료: https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=3&cciNo=2&cnpClsNo=2&csmSeq=631 . 현재 자체 환불 정책의 적용 범위를 오프라인 1개월 이내 강의로 명시하며, 녹화 콘텐츠·장기 강의 판매 전에는 해당 상품의 고지·청약철회 기준을 별도로 정한다.

현재 PG 상태는 `registration_pending`, checkoutEnabled=false. 카드 승인·자동 환불·토스 정산 조회는 아직 연결하지 않았다. 테스트/운영 키 확보 후 서버 승인 API, 금액·주문 검증, 멱등 취소 API, 검증된 웹훅, 결제대사 및 운영 심사를 별도 완료해야 한다. 서버 키는 승인된 Vercel Production 환경에서만 관리하고 클라이언트 번들·소스·문서에 넣지 않는다. 계약 동의·가입 비용·본인 인증은 사용자가 최종 확인한다.

## 심사 전용 계정

사용자가 2026-10-19에 테스트 계정 생성 및 ID·비밀번호를 토스 신청서에 전달하도록 승인했다. `scripts/prepare-toss-review-account.mjs --set-initial-password`는 별도 Supabase Auth 계정을 만들고 서버에서 기존 `lms_link_identity`로 일반 회원 프로필만 연결한다. 관리자·운영·회계 역할은 부여하지 않으며 기존 회원·주문·수납·환불·수강 기록을 변경하지 않았는지 비교한다. 이 운영용 계정은 강제 가입정보 입력 대상에서 제외하되 전화번호나 개인정보·알림톡·마케팅 동의는 임의로 만들지 않는다.

무작위 전용 비밀번호는 첫 발급 시에만 설정하며 다시 실행해도 기존 비밀번호를 회전하지 않는다. 계정 정보는 Git·Vercel 배포에서 제외된 `.local-data/toss-review-account.json`, 비밀번호는 권한 0600의 `.local-data/toss-review-credentials.json`에만 저장한다. 터미널·채팅·소스에 출력하지 않는다. 심사가 끝난 뒤에는 관리자 회원 관리에서 해당 계정을 중지할 수 있다.

`/login`과 공통 로그인 모달에서 등록된 이메일 계정의 비밀번호 로그인을 제공한다. 인증은 Supabase Auth가 처리하며 기존 회원 프로필이 연결된 계정만 LMS 세션을 사용한다. 이메일 기반 자체 회원가입·이메일만으로 기존 회원 병합·관리자 승격은 추가하지 않는다. 카카오·구글 가입 흐름은 유지한다.

검증: `scripts/test-toss-review-account.mjs`에서 실제 비밀번호 로그인·잘못된 비밀번호 차단·본인 프로필 RLS·관리 API 거절·다른 회원 금융정보 차단·빈 본인 수납 내역을 확인한다. 브라우저에서도 이메일 로그인 후 본인 신청 목록으로 이동하는 것을 확인했다. 이 검증은 실제 수강신청·결제·환불을 만들지 않는다.

공식 참고: https://docs.tosspayments.com/guides/v2/payment-window/integration , https://docs.tosspayments.com/reference , https://docs.tosspayments.com/reference/using-api/api-keys .

## 개발 연결 순서

계약 전에도 개발자 계정의 테스트 키로 연동할 수 있다. 신규 구현은 SDK v2를 사용하고 일회성 수강료 결제부터 연결한다. 현재의 무통장입금·법인 계산서 주문, 기존 정산·CRM·추천 이력은 유지한다.

1. 테스트 전용 주문과 운영 주문을 구분하고, 로그인 회원이 소유한 유효한 미결제 주문에서 서버가 주문번호·금액·과정명을 확정한다. 전화번호나 이메일을 customerKey로 사용하지 않는다.
2. 서버 승인 시 DB의 주문 소유권·상태·금액을 다시 확인한다. 결제 성공 URL에 도착했다는 이유만으로 결제 완료나 수강 승인을 기록하지 않는다.
3. 승인 결과의 주문번호·금액·상태를 확인한 뒤 결제 식별자를 유일하게 저장한다. 중복 호출·타임아웃·웹훅 재전송에 대해 중복 수납과 중복 수강 승인을 방지한다.
4. 취소·환불은 기존 권한과 환불 가능 금액을 검사하고 멱등 키를 사용한다. 외부 취소 성공 결과를 확인하기 전에는 환불 완료로 기록하지 않는다. 웹훅은 알림 내용만 신뢰하지 않고 토스 조회 결과와 대사한다.
5. 테스트 키로 승인·실패·사용자 취소·중복 호출·부분/전액 환불·위변조 금액·다른 회원 주문 접근을 검증한다. 테스트 결과를 실제 수납·정산 합계에 포함하지 않는다.
6. 계약·카드사 심사 완료 및 라이브 키 구성을 확인한 후 Production에서 실제 결제를 활성화한다. 시크릿 키는 채팅·Git·클라이언트 번들에 남기지 않고 Vercel Production 서버 환경변수로만 관리한다.

이 순서는 구현 요구사항이며, 현재 카드 승인 API나 자동 환불이 구현됐다는 의미는 아니다.
