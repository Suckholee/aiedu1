# 토스페이먼츠 신청·연결 상태

2026-10-19. 사용자가 현재 상태를 **아직 신청 전**으로 확인했다. 이전 작업의 사업자 확인·연락처 입력·이메일 인증 기록은 신청서 작성 중인 기록이며, 정식 접수·계약 완료로 취급하지 않는다. 대표자 본인인증 완료도 확인되지 않았다. 민감한 본인인증 정보는 저장소에 기록하지 않는다.

공식 신청 화면을 다시 열어 네오앤피터의 기존 사업자등록증으로 사업자를 확인했다. 현재 일반 신청 / 퀵오픈 선택 단계이며 사용자 선택을 기다린다. 대상 사이트는 https://aiedu1.vercel.app 이다. 일반 신청은 심사 후 오픈하며 가입비·연관리비가 있고, 퀵오픈은 당일 오픈 가능·가입비 면제 대신 심사 확정 전 정산이 보류된다. 실제 적용 조건은 해당 신청 화면과 계약에서 최종 확인한다.

현재 PG 상태는 `registration_pending`, checkoutEnabled=false. 카드 승인·자동 환불·토스 정산 조회는 아직 연결하지 않았다. 테스트/운영 키 확보 후 서버 승인 API, 금액·주문 검증, 멱등 취소 API, 검증된 웹훅, 결제대사 및 운영 심사를 별도 완료해야 한다. 서버 키는 승인된 Vercel Production 환경에서만 관리하고 클라이언트 번들·소스·문서에 넣지 않는다. 계약 동의·가입 비용·본인 인증은 사용자가 최종 확인한다.

공식 참고: https://docs.tosspayments.com/guides/v2/payment-window/integration , https://docs.tosspayments.com/reference , https://docs.tosspayments.com/reference/using-api/api-keys .

## 개발 연결 순서

계약 전에도 개발자 계정의 테스트 키로 연동할 수 있다. 신규 구현은 SDK v2를 사용하고 일회성 수강료 결제부터 연결한다. 현재의 무통장입금·법인 계산서 주문, 기존 정산·CRM·추천 이력은 유지한다.

1. 테스트 전용 주문과 운영 주문을 구분하고, 로그인 회원이 소유한 유효한 미결제 주문에서 서버가 주문번호·금액·과정명을 확정한다. 전화번호나 이메일을 customerKey로 사용하지 않는다.
2. 서버 승인 시 DB의 주문 소유권·상태·금액을 다시 확인한다. 결제 성공 URL에 도착했다는 이유만으로 결제 완료나 수강 승인을 기록하지 않는다.
3. 승인 결과의 주문번호·금액·상태를 확인한 뒤 결제 식별자를 유일하게 저장한다. 중복 호출·타임아웃·웹훅 재전송에 대해 중복 수납과 중복 수강 승인을 방지한다.
4. 취소·환불은 기존 권한과 환불 가능 금액을 검사하고 멱등 키를 사용한다. 외부 취소 성공 결과를 확인하기 전에는 환불 완료로 기록하지 않는다. 웹훅은 알림 내용만 신뢰하지 않고 토스 조회 결과와 대사한다.
5. 테스트 키로 승인·실패·사용자 취소·중복 호출·부분/전액 환불·위변조 금액·다른 회원 주문 접근을 검증한다. 테스트 결과를 실제 수납·정산 합계에 포함하지 않는다.
6. 계약·카드사 심사 완료 및 라이브 키 구성을 확인한 후 Production에서 실제 결제를 활성화한다. 시크릿 키는 채팅·Git·클라이언트 번들에 남기지 않고 Vercel Production 서버 환경변수로만 관리한다.

이 순서는 구현 요구사항이며, 현재 카드 승인 API나 자동 환불이 구현됐다는 의미는 아니다.
