# UI/UX 기본 규칙

폼은 사용자가 익숙한 방식으로 입력할 수 있게 하고, 표시 형식에 맞추는 작업은 시스템이 처리한다. 같은 정보는 가입·신청·관리 화면에서 같은 방식으로 입력한다.

## 전화번호 입력

- 숫자만 입력해도 자동으로 하이픈을 표시한다. 예: `01012345678` → `010-1234-5678`.
- `type="number"`는 사용하지 않는다. 맨 앞의 0을 유지하고 `type="tel"`, `inputMode="numeric"`, `autoComplete="tel"`을 사용한다.
- 공통 `components/ui/phone-input.tsx`의 `PhoneInput`을 재사용한다. 화면마다 하이픈 처리를 따로 만들지 않는다.
- 숫자 입력뿐 아니라 하이픈·공백이 있는 번호와 `+82` 형식의 붙여넣기도 받아들인다.
- 중간 자리 수정, 선택 영역 교체, Backspace/Delete가 자연스러워야 한다. 자동 하이픈에 커서가 갇히거나 숫자를 입력할 때마다 맨 끝으로 이동하면 안 된다. 모바일 소프트웨어 키보드의 삭제도 처리한다.
- 안내 예시는 `010-1234-5678`로 통일한다. 하이픈을 사용자가 직접 입력하도록 요구하지 않는다.
- 서울 지역번호·일반 지역번호·대표번호도 공통 표시 함수에서 처리한다. 전화번호를 길이에 맞춰 조용히 잘라내지 않는다.
- 표시 형식과 유효성 검증은 분리한다. 자동 정렬은 휴대전화 소유자 인증이 아니다. 회원 휴대전화는 기존 서버 검증에서 숫자로 정규화하고 11자리를 확인한다.
- 저장된 기존 번호는 표시할 때만 정렬하고, 화면 진입만으로 기존 고객·결제 기록을 변경하지 않는다.

## 확인 기준

숫자 연속 입력, 형식 있는 번호 붙여넣기, 가운데 수정, 자동 하이픈 앞뒤 삭제, 전체 지우기, 모바일 숫자 키패드를 확인한다. 수강신청이나 결제를 실제 접수하지 않고 입력란만으로 검증한다.

적용 화면: 회원가입·내 회원정보, 수강신청, 수강신청 모달, 관리자 회원 정보·CRM 연락처, 블로그 연락처 프로필.
