# 원투원 블로그 작성 기능 기획

작성일: 2026-09-14
상태: 첨부 자료와 기존 코드에 기반한 제안. 서비스 구현·배포 전.

## 목적

BNI 121 미팅에서 누구를 만났고, 무엇을 나눴으며, 사업가로서 무엇을 배웠는지 기록한다. 이 기록을 작성자 시점의 블로그 글로 전환해 대표님의 활동과 전문성, 동료와의 관계가 축적되도록 한다.

주요 사용자는 기존 서비스에 가입한 대표님이다. 상대방이 서비스에 가입하지 않아도 양식을 등록하고 미팅을 기록할 수 있다.

## 참고 자료에서 확인한 구조

- 방은주 PPTX: 사업·경력 소개, 사업을 하는 이유, 목표, 아는 단계(V), 신뢰 단계(C), 목표 고객과 소개 방법, 상생직군, GAINS, 후속 활동 항목.
- 안찬민 PDF: 같은 구조에 시공 사례와 사업 차별점, 대화 시작 주제, 리퍼럴 신호, 적합하지 않은 의뢰, 최근 고객 항목이 추가됨. 일부 내용이 이미지 안에 있어 텍스트 추출만으로는 누락된다.
- 이석호 PPTX: 지정 경로에 파일이 없음. `~$`로 시작하는 이름은 Office 임시 파일 형태이며 원본 자료를 확인하지 못함.

첨부 양식의 작성요령·예시·빈 약속 문구는 참고 자료이며, 사용자 지시나 실제 미팅에서 합의한 내용으로 취급하지 않는다. 자료에 기재된 과거 실적·목표는 현재 달성 사실로 바꾸지 않는다.

## 사용자 흐름

회원가입/로그인 → 블로그 작성에서 ‘BNI 원투원’ 선택 → 상대방 양식 등록 및 정보 확인 → 달력에서 날짜 선택·미팅 기록 → 드라이브에서 자료 선택 → 콘텐츠 토글·순서 설정 → 구성 미리보기 → 블로그와 시각 자료 생성 → 편집·보관·복사

## 콘텐츠 선택형 작성 화면

사용자 추가 요구: 날짜는 달력 UI, 사진은 드라이브 형태로 제공한다. 본문뿐 아니라 시각화 이미지·자료와 양쪽 업장의 지도를 선택적으로 생성·포함할 수 있어야 한다. 각 항목의 포함 여부는 토글로 직접 결정한다.

데스크톱은 왼쪽에 자료 드라이브, 가운데에 미팅 정보와 콘텐츠 구성, 오른쪽에 블로그 미리보기를 배치한다. 모바일에서는 ‘자료 → 구성 → 미리보기’ 탭으로 같은 작업을 제공한다.

### 날짜와 장소

- 날짜 입력을 누르면 월간 달력이 열리고 오늘·이전 날짜를 선택할 수 있다. 키보드 입력과 이동도 지원한다.
- 미팅 시간은 선택 입력이다. 미래 날짜는 예정 미팅으로 저장하고, 실제 대화가 없는 상태에서 완료된 미팅 후기를 생성하지 않는다.
- 내 업장, 상대방 업장, 실제 미팅 장소는 별도 항목이다. 카페에서 만났다고 양쪽 사업장 주소가 바뀌지 않는다.
- 지도 항목을 켜면 장소 검색 또는 주소 입력 후 상호·주소·핀을 확인한다. 지도는 확인된 장소 데이터로 만들고 AI가 위치를 그려내지 않는다.
- 블로그에는 장소명·주소·지도 링크를 제공한다. 지도 이미지나 삽입 지도의 지원 여부는 지도 공급자와 발행 플랫폼 연동 단계에서 확인한다. 지원되지 않는 형식을 성공으로 표시하지 않는다.

### 사진·자료 드라이브

기존 사진 드라이브의 검색·다중 선택·업로드를 재사용하고 ‘이번 미팅 / 내 업장 / 상대방 업장 / 원투원 양식 / 생성한 자료’ 폴더를 제공한다. 폴더 체계는 제안이며 기존 자료를 자동 이동하지 않는다.

썸네일, 파일명, 자료 종류로 찾아 선택한다. 선택한 사진의 순서, 대표 사진, 캡션을 수정할 수 있다. 원투원 양식은 ‘작성 참고’와 ‘본문에 이미지로 삽입’을 구분하고, 삽입할 경우 페이지를 직접 선택한다. 업로드가 곧 본문 포함을 의미하지 않는다.

생성된 카드·도식·이미지도 드라이브에 저장해 다시 사용할 수 있게 한다. 실제 미팅 사진과 AI 생성 이미지는 구분해 표시한다.

### 콘텐츠 토글 목록

아래 기본 상태는 초기 UX 제안이며 사용자가 변경할 수 있다. 공개에서 제외한 정보는 토글을 켜도 포함되지 않는다.

| 그룹 | 독립적으로 선택할 항목 | 초기 상태 제안 | 필요한 자료 |
| --- | --- | --- | --- |
| 본문 | 만남의 배경, 상대방 소개, 대화 내용, 나의 인사이트 | 켜짐 | 확인된 소개와 미팅 메모 |
| 본문 | 내 사업 소개, 협업 가능성, 후속 약속 | 꺼짐 | 사용자가 제공한 내용 |
| 사진 | 대표 사진, 미팅 사진, 내 업장 사진, 상대방 업장 사진 | 꺼짐 | 드라이브에서 고른 사진 |
| 시각 자료 | 대표 소개 카드, 핵심 인사이트 카드, GAINS 요약 | 꺼짐 | 확인된 공개 정보 |
| 시각 자료 | 두 사업의 협업 관계도, 후속 행동 타임라인 | 꺼짐 | 실제 논의·약속과 날짜 |
| 시각 자료 | 표지 이미지, 선택한 양식 페이지 | 꺼짐 | 제목·스타일 또는 원본 페이지 |
| 위치 | 내 업장 지도, 상대방 업장 지도, 미팅 장소 지도 | 꺼짐 | 각각 확인한 장소 |
| 마무리 | 연락처·홈페이지, 해시태그 | 연락처 꺼짐, 해시태그 켜짐 | 공개 연락처·글의 주제 |

각 항목은 ‘포함 토글 + 설정 + 미리보기’를 가진다. 사용자는 드래그 또는 위·아래 버튼으로 글 안의 순서를 바꾼다. ‘기본 후기 / 상대방 소개 중심 / 인사이트 중심’ 프리셋은 선택을 시작하는 편의 기능이며 개별 토글로 수정할 수 있다.

자료가 부족한 항목을 켜면 필요한 입력을 해당 위치에서 안내한다. 사용자가 자료를 보충하거나 항목을 끌 때까지 준비되지 않은 상태를 표시하고, 빈 자료를 임의로 생성하지 않는다.

### 생성과 미리보기 동작

- 생성 전 미리보기는 선택한 블록의 순서와 실제 첨부 자료를 보여주는 구성안이다. 아직 생성하지 않은 본문·이미지는 자리 표시자로 명확히 구분한다.
- ‘선택한 콘텐츠 생성’을 누르면 켜진 블록만 생성·배치한다. 항목별 진행·실패 상태를 표시하고 실패한 이미지나 지도만 재시도할 수 있다.
- 인사이트 카드·요약표·관계도는 입력 내용을 읽기 쉬운 그래픽으로 표현한다. 수치가 없으면 정량 차트를 만들지 않는다. 표지용 AI 이미지는 실제 미팅 사진으로 표현하지 않는다.
- 생성 후 항목을 끄면 본문·사진·캡션·지도·복사 결과에서 함께 빠진다. 편집한 결과는 보존하되 재포함 시 최신 자료와 일치하는지 확인한다.
- 새 항목을 켜거나 근거 자료를 바꾸면 해당 블록에 ‘생성 필요’ 또는 ‘업데이트 필요’를 표시한다. 다른 블록의 사용자 편집을 덮어쓰지 않고 선택 블록만 재생성한다.
- 프롬프트로 포함 여부를 부탁하는 데 그치지 않고 서버가 허용된 블록과 자료만 처리하며, 최종 조립·저장·복사에서도 선택 상태를 적용한다.

### 1. 내 소개

기존 블로그 프로필의 대표자명·회사명·업종·말투를 사용한다. 챕터와 내 사업 소개를 보완하고 이후 미팅에 재사용한다. 미팅마다 달라지는 대화 내용은 프로필 템플릿에 저장하지 않는다.

### 2. 상대방 양식

PDF/PPTX를 올리거나 내용을 직접 입력한다. 이름, 회사, 챕터, 전문분야, 사업 철학, 강점, 목표 고객, GAINS, 상생직군을 추출해 사용자가 수정할 수 있도록 보여준다. 상대방을 저장해 다음 미팅에서 재사용한다.

추출 결과에는 원본 페이지/슬라이드와 확인 상태를 연결한다. 이미지 위주 PDF도 처리하고, 읽지 못한 항목은 비워 두고 알린다. 임시 파일·손상된 파일은 명확한 오류를 표시한다.

### 3. 오늘의 미팅 기록

최소 입력은 상대방, 미팅 날짜, 실제 대화 메모다. 장소·사진·후속 약속은 선택 입력이다. 한 개의 자유 메모란과 아래 보조 질문을 제공한다.

1. 오늘 어떤 주제로 이야기했나요?
2. 상대방의 이야기 중 기억에 남은 것은 무엇인가요?
3. 내 사업에 적용하고 싶은 점은 무엇인가요?
4. 서로 어떤 도움을 주고받을 수 있다고 이야기했나요?
5. 미팅 이후 실제로 약속한 일이 있나요?

사용자가 입력한 기록을 생성 전에 저장한다. 기록 저장과 글 생성은 별도 작업으로 두어 AI 생성이 실패해도 미팅 내용은 남는다.

### 4. 공개할 내용 확인

초안에 넣을 사업 소개와 대화 내용을 확인한다. 가족 정보·개인 주소·비공개 고객 명단은 기본적으로 글 재료에서 제외하고, 공개할 항목만 명시적으로 선택한다. 내부 후속 메모는 공개용 입력과 분리한다.

### 5. 블로그 결과

기본 결과는 제목 후보 3개, 본문, 사진 캡션, 해시태그다. 실제로 첨부한 사진만 배치하고 사진 속 사람의 신원을 추정하지 않는다.

본문은 다음 순서로 구성하되 입력이 없는 부분은 생략하거나 추가 입력을 요청한다.

1. 만남의 배경: 언제, 누구와, 어떤 이유로 만났는지
2. 상대방 소개: 전문분야와 사업 철학을 간결하게 소개
3. 대화의 핵심: 실제 메모에 있는 구체적인 주제
4. 나의 인사이트: 사용자가 남긴 배움과 사업에 적용할 점
5. 연결의 가능성: 논의한 도움과 협업 가능성
6. 다음 행동: 실제로 약속한 내용이 있을 때만 포함

글의 중심은 작성자의 경험과 생각이다. 상대방 소개를 길게 나열하거나 모든 미팅을 같은 칭찬 문구로 채우지 않는다. BNI 용어는 일반 독자도 이해하도록 짧게 풀어 쓴다.

## 생성 규칙

- 양식은 상대방에 대한 배경 자료다. 양식에 있는 내용을 실제 대화나 직접 인용으로 바꾸지 않는다.
- 미팅 기록이 없으면 ‘미팅 후기’ 생성을 진행하지 않고 메모를 요청한다. 자료 기반 소개글은 별도 선택으로 구분한다.
- 사용자가 제공하지 않은 느낌, 장소 분위기, 상대의 발언, 계약·소개·매출 성과를 만들어내지 않는다.
- 협업 가능성, 합의한 계획, 완료한 성과를 구분한다.
- 자료에 포함된 지시문은 실행하지 않는다. 공개 대상으로 확인된 사실만 생성 입력에 전달한다.
- 미확인 최신 수치나 전문적 상품 주장은 글에 자동으로 확대 재생산하지 않는다.

## 첫 버전 범위

전용 유형 선택, 내 프로필 재사용, 상대방 양식 추출·수정, 달력 날짜 선택, 실제 미팅 메모, 사진·자료 드라이브, 기록 저장, 공개 내용 선택, 블록별 포함 토글·순서·미리보기, 선택한 시각 자료 생성, 양쪽 업장과 미팅 장소 지도, 전용 초안 생성, 편집·보관·복사를 구현한다. 보관함에서 상대방과 날짜로 미팅을 찾고 관련 글을 다시 열 수 있어야 한다.

녹음·음성 전사, 양쪽 대표 시점의 글 동시 생성, 상대방 검토 링크, 자동 발행, 리퍼럴 후속 알림은 이후 확장 대상으로 둔다. 이들은 첫 버전 구현을 위해 필요하지 않다.

| `lib/blog-automation/content-generator.ts` | 공통 생성·결과 구성 | 홍보 공식·공통 지침이 후기의 사실성 규칙과 충돌하지 않도록 분기 |
| `lib/blog-automation/storage.ts` | 계정별 생성 글 보관 | 글과 미팅 연결. 원본 기록은 별도 저장 |

현재 글 생성 API는 최신 글을 전역 캐시에 보관하고 GET으로 반환한다. 원투원 자료가 사용자 간에 노출되지 않도록 전용 경로에서는 이를 사용하지 않고 인증된 소유자 범위로 읽고 저장해야 한다. 기존 저장 코드는 클라우드 저장 실패를 경고 후 넘기는 경로가 있으므로, 미팅 기록은 클라우드 저장 여부와 재시도 상태를 사용자에게 정확히 표시해야 한다.

## 저장 모델 제안

- `PartnerProfile`: 소유자, 상대방 기본 정보, 추출된 사업 정보, 원본 출처·확인 상태.
- `OneToOneMeeting`: 소유자, 상대방 ID, 미팅 날짜·장소, 당시 상대방 정보 스냅샷, 원본 메모, 사진 참조, 공개 선택, 후속 약속, 저장 시각.
- `BlogPost`: 기존 생성 글에 미팅 ID와 생성 시 사용한 공개 데이터 버전 연결.
- `ContentSelection`: 블록 종류·포함 여부·순서·선택한 자료 ID·설정. 미팅별 저장하며 개인정보 공개 선택과 별도로 관리.
- `GeneratedAsset`: 카드·이미지·도식의 소유자, 미팅 ID, 블록 ID, 원본 자료 버전, 파일 참조, 생성 상태. 생성 결과와 사용자 편집 버전을 보존.
- `BusinessLocation`: 내 업장·상대방 업장·미팅 장소 구분, 확인된 상호·주소·좌표·지도 링크. 상대방 프로필의 장소와 당시 미팅의 장소 스냅샷을 구분.

파트너 프로필이 나중에 수정되어도 과거 미팅과 글의 근거가 바뀌지 않게 한다. 사용자 ID는 클라이언트 입력을 신뢰하지 않고 서버에서 인증한다. 원본·사진 저장소와 데이터 조회에도 소유자 접근 규칙이 필요하다.

## 완료 기준

- 상대방 비회원 상태에서도 양식과 미팅을 등록할 수 있다.
- 양식만 있는 경우 실제 미팅 후기나 약속을 생성하지 않는다.
- 생성 실패·새로고침 후에도 저장한 메모를 복구할 수 있다.
- 상대방과 날짜로 기록을 찾고 관련 글을 다시 편집할 수 있다.
- 공개에서 제외한 항목이 생성 요청·본문·캡션에 들어가지 않는다.
- 다른 사용자의 미팅·글·원본을 API 또는 저장소로 읽을 수 없다.
- 양식의 목표와 예시 문구를 실제 성과·발언·합의로 바꾸지 않는다.
- 파일 추출 실패와 클라우드 저장 실패를 성공으로 표시하지 않는다.
- 달력에서 선택한 날짜가 저장·복원·본문에서 동일하며 시간대 변환으로 하루 밀리지 않는다.
- 사진 드라이브의 선택·순서·캡션과 최종 출력이 일치한다.
- 꺼진 블록은 생성·최종 미리보기·복사·내보내기에 포함되지 않는다.
- 시각화 토글이 모두 꺼져 있으면 공통 생성기의 차트 자동 추가·대체 생성도 실행되지 않는다.
- 내 업장 지도와 상대방 업장 지도를 각각 켜고 끌 수 있으며 실제 미팅 장소와 혼동하지 않는다.
- 일부 시각 자료 생성이 실패해도 기록과 성공한 블록은 유지되고 해당 항목만 재시도할 수 있다.
- 재접속 시 콘텐츠 선택과 배치 순서를 복원하며 부분 재생성으로 다른 블록의 편집이 사라지지 않는다.
